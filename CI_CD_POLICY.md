# Политика CI/CD

## Схема CI/CD Pipeline
1.  **Этап: Commit**
    *   Запускается при пуше в ветки `feature/*`, `bugfix/*`.
    *   Действия: линтинг, сборка, запуск модульных тестов.
2.  **Этап: Build & Test (Сборка и тесты)**
    *   Запускается при мерже Pull Request в `main`.
    *   Действия: сборка артефакта, запуск интеграционных тестов, сканирование кода (SAST).
3.  **Этап: Deploy to Staging (Выкладка на стейджинг)**
    *   Запускается автоматически после успешного мержа в `main`.
    *   Действия: развертывание артефакта в staging-окружение, запуск e2e-тестов.
4.  **Этап: Deploy to Production (Выкладка на продакшен)**
    *   Запускается **вручную** (approval) из интерфейса CI/CD.
    *   Действия: развертывание с blue-green или canary стратегией, smoke-тесты.

## Роли и права
*   **Разработчик:** Может запускать пайплайны для feature-веток, создавать MR. Не имеет прав на деплой в prod.
*   **Lead Developer / DevOps Engineer:** Имеет права на approval и запуск деплоя в production.
*   **Maintainer:** Может вносить изменения в конфигурацию пайплайнов (`.gitlab-ci.yml`, `Jenkinsfile` и т.д.).
